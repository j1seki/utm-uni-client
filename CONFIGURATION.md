# Configuration

`utm-web` can be configured with a JSON file, environment variables and command
line flags. Precedence is:

1. Command line flags
2. Environment variables
3. JSON config file
4. Built-in defaults

The default config file is:

| Platform | Path |
| --- | --- |
| Linux | `$XDG_CONFIG_HOME/utm-web/config.json` or `~/.config/utm-web/config.json` |
| macOS | `~/.config/utm-web/config.json` |
| Windows | `%APPDATA%\utm-web\config.json` |

Set `UTM_WEB_CONFIG_DIR` to move both the config file and the default client
certificate, or pass `--config` / `--cert` explicitly.

## Example

```json
{
  "listen": "127.0.0.1:8080",
  "client_certificate": "~/.config/utm-web/client.pem",
  "certificate_password": "password",
  "allow_untrusted": false,
  "max_sessions": 32,
  "session_idle_timeout_secs": 3600,
  "public_url": null,
  "profiles": [
    {
      "id": "4f3c2a1b0e9d8c7b6a5f",
      "name": "Studio Mac",
      "host": "studio.local",
      "port": 21589,
      "fingerprint": "AA:BB:CC:DD:...",
      "password": "utm-remote-password",
      "trusted": true,
      "last_connected": 1730000000
    }
  ]
}
```

The config file is written atomically with mode `0600` on Unix. It contains UTM
passwords in plain text, so treat it as a secret.

## Settings

| Key | Env | Default | Description |
| --- | --- | --- | --- |
| `listen` | `UTM_WEB_LISTEN` | `127.0.0.1:8080` | Address and port for the web server. |
| `client_certificate` | `UTM_WEB_CERT` | `<config dir>/client.pem` | Client certificate PEM used for mutual TLS to UTM. |
| `certificate_password` | `UTM_WEB_CERT_PASSWORD` | `password` | Password for an encrypted PKCS#8 private key. |
| `allow_untrusted` | `UTM_WEB_ALLOW_UNTRUSTED` | `false` | Accept unknown UTM fingerprints without confirmation. **Not recommended.** |
| `max_sessions` | `UTM_WEB_MAX_SESSIONS` | `32` | Maximum number of concurrent SPICE display sessions. |
| `session_idle_timeout_secs` | `UTM_WEB_SESSION_TIMEOUT` | `3600` | Close a display with no viewers after this many seconds. Minimum 30. |
| `public_url` | `UTM_WEB_PUBLIC_URL` | unset | Optional external URL shown in the API status; useful behind a proxy. |
| `profiles` | — | `[]` | Saved UTM servers. Managed by the UI. |

`RUST_LOG` controls logging, for example `RUST_LOG=utm_web=debug`. The default
is `utm_web=info,warn`.

## Profiles

Profiles are created and edited from the web UI. Each profile contains:

| Field | Description |
| --- | --- |
| `id` | Random identifier generated by `utm-web`. |
| `name` | Display name. |
| `host` | UTM server hostname or IP address. |
| `port` | UTM Remote port, normally `21589`. |
| `fingerprint` | Pinned XOR connection fingerprint (server SHA-256 XOR client SHA-256). |
| `password` | UTM Remote password. Omitted if empty. Never returned by the API. |
| `trusted` | Whether the pinned fingerprint has been confirmed. |
| `last_connected` | Unix timestamp of the last successful connection. |

The browser receives `has_password` instead of the password itself. Changing a
profile's host, port, password, fingerprint or trust state disconnects the
upstream session so the next connection uses the new settings.

### Trust on first use

1. The first connection completes the TLS handshake and computes the connection
   fingerprint.
2. If no fingerprint is pinned, the API returns `409 Conflict` with
   `error: "untrusted"` and the fingerprint.
3. The UI shows the fingerprint. Compare it with UTM's Remote settings on the
   Mac and click **Trust server**.
4. `POST /api/profiles/{id}/trust` stores the fingerprint and reconnects.

If a pinned fingerprint changes later, the connection is refused with
`fingerprint_mismatch` until the profile is edited or re-trusted.

## Client certificate

UTM Remote uses mutual TLS. `utm-web` reads the same PEM layout as pyutmremote:
one certificate and one private key, in either order. Supported key blocks:

- `PRIVATE KEY` (PKCS#8, unencrypted)
- `RSA PRIVATE KEY` (PKCS#1)
- `EC PRIVATE KEY` (SEC1)
- `ENCRYPTED PRIVATE KEY` (PKCS#8, decrypted with `certificate_password`)

If the file does not exist, `utm-web` generates a self-signed RSA-4096 client
certificate with `O=UTM, CN=UTM Remote Client`, matching pyutmremote's profile.
Generation takes a few seconds. To generate it ahead of time:

```sh
./utm-web --generate-cert
```

The client fingerprint is the SHA-256 of the DER certificate. It is shown in
the web header and the `/api/status` response.

## Reverse proxy

`utm-web` has no user authentication. If it is not bound to loopback, add
authentication and TLS at the proxy.

### Caddy

```caddy
utm.example.com {
    basic_auth {
        alice $2a$14$...   # caddy hash-password
    }
    reverse_proxy 127.0.0.1:8080
}
```

Caddy forwards WebSocket upgrades automatically.

### nginx

```nginx
server {
    listen 443 ssl;
    server_name utm.example.com;

    ssl_certificate     /etc/ssl/utm.example.com.pem;
    ssl_certificate_key /etc/ssl/utm.example.com.key;

    auth_basic           "utm-web";
    auth_basic_user_file /etc/nginx/utm-web.htpasswd;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        proxy_buffering off;
    }
}
```

Set `public_url` to the external URL if you want the status endpoint to report
it:

```sh
UTM_WEB_PUBLIC_URL=https://utm.example.com ./utm-web --listen 127.0.0.1:8080
```

## systemd

```ini
[Unit]
Description=utm-web
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=utm-web
Group=utm-web
ExecStart=/usr/local/bin/utm-web --listen 127.0.0.1:8080
Environment=RUST_LOG=utm_web=info
Restart=on-failure
RestartSec=2
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/utm-web

[Install]
WantedBy=multi-user.target
```

If you use a dedicated user, set `UTM_WEB_CONFIG_DIR=/var/lib/utm-web` and make
sure the directory is owned by that user.

## Windows service

Run the executable with a service manager such as
[NSSM](https://nssm.cc/) or Task Scheduler. The config directory defaults to
`%APPDATA%\utm-web`; set `UTM_WEB_CONFIG_DIR` if the service account's profile
directory is not appropriate.
